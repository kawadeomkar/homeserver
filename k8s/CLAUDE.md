# k8s/

What Flux applies to the cluster: the platform in `infrastructure/`, the apps in `apps/`, and one directory of Flux
Kustomizations per setup in `clusters/`. Claude Code loads this file when it works on a file under `k8s/`; the root
`CLAUDE.md` holds what every session needs, and `roles/flux_bootstrap/README.md` how the cluster is handed to Flux.

## Checking the manifests

`kubeconform` is the usable gate for manifests — `kubectl --dry-run=client` is not, since it needs a live API server for OpenAPI validation. `kubectl` v1.36.2 (with Kustomize v5.8.1 embedded), `kubeconform` v0.8.0 and `kube-linter` v0.8.3 are what works locally. `just lint manifests` runs kubeconform strictly against the Kubernetes version Talos ships, with the schemas pinned to one commit and cached in `.cache/kubeconform`. `just lint manifests` runs kube-linter with `.kube-linter.yaml`: its default checks, minus three that contradict choices made here (read-only root filesystems, non-root users, memory limits), plus the liveness and readiness probe checks, a check that every container requests memory and one that rejects `imagePullPolicy: Always`. **It lints what Flux applies, not the files**: `scripts/ci/render_manifests.py` builds each path a setup's Flux Kustomizations apply with kustomize and substitutes the placeholder settings (`tests/fixtures/cluster-settings.yaml`) into `.cache/k8s-rendered/<setup>/`, because kube-linter silently skips an object it cannot decode, and a limit of `"${GPU_I915}"` is no quantity until Flux substitutes it (linting the raw files dropped Jellyfin's and Frigate's Deployments without a word). The script fails on a manifest no setup applies, and `test_k8s.py` checks that every quantity parses once substituted, which neither kubeconform (any string passes its schema) nor kube-linter reports. A workload that needs what a check forbids carries an `ignore-check.kube-linter.io/<check>` annotation saying why. Both tools come from `PATH` (Homebrew here, pinned by version and checksum in CI).

## Layout

**Manifest layout**: `k8s/clusters/<setup>/` holds Flux Kustomizations only; `k8s/infrastructure/` the platform (a controller's directory holds its namespace); `k8s/apps/<group>/` one app group per directory, applied as a unit by its own Flux Kustomization, with a `kustomization.yaml` listing its files, `namespace.yaml`, one file per app (its claim, Deployment, Service and Ingress), and a SOPS Secret once the owner makes it. Every object names its namespace; cluster-scoped ones none. A configMapGenerator's source is a `.tmpl` file.

**Flux applies `k8s/clusters/<setup>/`** (`nas` with a NAS, `local` without), which holds only Flux Kustomizations, each applying one path: `infra-controllers` (`k8s/infrastructure/controllers/<setup>/`: MetalLB, Traefik, cert-manager and local-path-provisioner from `common/`, plus csi-driver-nfs with a NAS), then, depending on it, `infra-configs` (`k8s/infrastructure/configs/`: what needs the controllers' CRDs or namespaces: MetalLB's address pool, Traefik's allowlist and HSTS), `infra-tls` (`k8s/infrastructure/tls/`: the cluster's CA, its issuer, the wildcard and Traefik's default certificate, on its own because nothing waits for it: a cluster that cannot decrypt the CA, such as a test host's with an age key of its own, runs everything else on Traefik's own certificate) and `infra-storage` (`k8s/infrastructure/storage/<setup>/`: the static volumes, the same names in both setups).

**Every Flux Kustomization has `decryption` (`sops-age`) and `postBuild.substituteFrom` (`cluster-settings`)**, harmless where unused, so a SOPS Secret or a `${VAR}` added later never stalls one.

**Each controller's Namespace, with its Pod Security label and a comment, lives in that controller's own directory**, in the same Flux Kustomization: in `configs/` it would deadlock the platform (a privileged pod rejected in an unlabelled namespace, `infra-controllers` never ready, nothing after it applied).

**Substitution rules**: Flux replaces `${VAR}` in every built manifest and, with strict substitution on (the FluxInstance's patch), fails the build on one that is not a setting; shell scripts and app configs use `$var` or `$${var}` (a literal `${var}`), a ConfigMap holding a foreign template wholesale carries `kustomize.toolkit.fluxcd.io/substitute: disabled`, and an optional value uses `${VAR:=default}`. A configMapGenerator's source files take a non-YAML extension (`.tmpl`), so neither kubeconform nor `test_k8s.py` reads them as objects.

local-path-provisioner is vendored whole (`controllers/common/local-path/local-path-storage.yaml`, v0.0.37) with one edit, its Namespace's labels; everything else is a kustomize patch (the StorageClass renamed `local`, default, `Retain`, `defaultVolumeType: local`; requests; the node path `/var/mnt/local-path-provisioner`; the helper image pinned by digest). Its README says how to re-vendor it, by hand, the whole file.

MetalLB runs layer 2 only (`frrk8s.enabled: false`, which 0.16.1 defaults to true); Traefik (chart 41.7.1 from its OCI registry) is the default IngressClass on `LB_TRAEFIK_IP` with `allocateLoadBalancerNodePorts: false`, a finite read timeout on each entrypoint (10 minutes on `web`, for what Jellyfin's apps send, an hour on `websecure`, for uploads), and the CRD provider's legacy names set explicitly (`--providers.kubernetescrd.safeNaming=false`), since the entrypoints name their Middlewares `<namespace>-<name>@kubernetescrd` and collision-safe naming would spell them `<namespace>_<name>`, every entrypoint deleting header names that alias another (`aliasHeadersStrategy: delete`: `X_Forwarded_For` reaches a PHP or Python backend as `X-Forwarded-For`), and `web` and `websecure` refusing an encoded NUL in a path while allowing the other encoded characters, which Nextcloud's file names hold; a start can log that the allowlist does not exist for `web-to-443@internal`, a known race (traefik#9779) during which that router stays closed; csi-driver-nfs creates no StorageClass and has `feature.enableFSGroupPolicy: false`, so kubelet never chowns a whole NFS volume, and takes no volume snapshots (the NAS snapshots the datasets worth it): `externalSnapshotter.enabled` off leaves out the snapshot controller and its CRDs, and `controller.enableSnapshotter` off the controller pod's snapshot sidecar, which the chart runs either way and which, without the CRDs, logs a failure every few seconds.

**Every chart is pulled by something its publisher cannot move**: Traefik's, cert-manager's, kube-prometheus-stack's and MetalLB's (its OCI artifact, the same release its Helm repository serves) by the digest beside their tag in their `OCIRepository`, and csi-driver-nfs's from upstream's Git repository at the commit tagged for its release (a `GitRepository` on the release branch, its chart path in the HelmRelease), since its Helm repository's index points versions at files on branches. `test_k8s.py` refuses an unpinned source or any `HelmRepository`, and `just lint charts` renders each pin, refusing a tag that names another digest; a bump moves tag and digest, or commit and path, together. Every chart's components carry requests, which `just lint charts` enforces on the rendered output with `.kube-linter-charts.yaml`.

`tests/policy/test_k8s.py` follows each Flux Kustomization's path through the kustomization files to check: every Kustomization decrypts and substitutes; every `${VAR}` without a default is a key of each setup's settings (resolved through the inventory, as the role does); every namespace is declared once and every namespaced object names a declared one (or `kube-system`, `flux-system`: `UNDECLARED_NAMESPACES`; `SYSTEM_NAMESPACES` stays `kube-system`, what Pod Security exempts); a controller's namespace comes with it; no PodDisruptionBudget; and, after `just lint charts`, the charts' host paths (`CHART_HOST_PATHS`) and privileged pods.

## Apps

**The apps live in `k8s/apps/<group>/`, one Flux Kustomization each** (`apps-media`, `apps-nextcloud`, `apps-photoprism`, `apps-frigate`, `apps-homepage` in `k8s/clusters/<setup>/apps.yaml`), each depending on `infra-configs` and `infra-storage`, with `prune` and `wait`; both setups list the same apps. **A host runs the groups `local.yml`'s `kubernetes_apps` names** (unset, every group; `[]`, the platform alone), out of `kubernetes_app_groups` (`group_vars/all/kubernetes.yml`), which `test_k8s.py` checks against `apps.yaml`; `roles/flux_bootstrap` leaves the others out (above). A group is one namespace, declared in its own `namespace.yaml`: `media` holds sonarr, radarr, prowlarr, sabnzbd, seerr (Jellyseerr's successor), jellyfin and FileBrowser Quantum (FileBrowser's archived v2.63.18 is never deployed), sharing one claim `media` on the library mounted once at `/data`, so a download moves into the library as a rename; `nextcloud` and `photoprism` each hold the app and its MariaDB as two Deployments (`nextcloud-db`, `photoprism-db`), `frigate` and `homepage` one app. Home Assistant is a VM of its own (Home Assistant OS), not a manifest.

**Every app** runs one replica replaced whole (`Recreate`), Homepage aside (two, rolling one at a time, spread with a preferred anti-affinity); has liveness and readiness probes, and a startup probe where it migrates before it listens (Nextcloud's `occ upgrade`, both MariaDBs' first initialisation, PhotoPrism: ten minutes; the *arr apps and seerr: five), since a liveness probe that killed a migration half way would leave it broken; mounts no service account token (no app reads the API; Homepage's Kubernetes mode is off); gives every container `allowPrivilegeEscalation: false` under the `RuntimeDefault` seccomp profile, LinuxServer.io images keeping the default capabilities their s6 init needs but NET_RAW (raw sockets, which would let a pod forge its neighbours' packets; Frigate, PhotoPrism and both MariaDBs drop it too) and running as root until s6 drops to `PUID`/`PGID` 1000, PhotoPrism likewise (its image starts through s6-overlay too, which exits at once as a non-root user, so it starts as root and its entrypoint drops to `PHOTOPRISM_UID`/`PHOTOPRISM_GID` 1000 with setpriv, with `PHOTOPRISM_DISABLE_CHOWN` sparing the storage volume a recursive chown at every start), seerr, FileBrowser and Homepage running as 1000 with every capability dropped; reads `TZ` and its host (`<app>.${DOMAIN}`, Homepage at the apex) from the cluster's settings; is a `ClusterIP` Service behind a Traefik Ingress, Frigate's camera streams aside (`frigate-rtsp`, a LoadBalancer on `LB_FRIGATE_IP` with `allocateLoadBalancerNodePorts: false`); and labels everything `app.kubernetes.io/name`. Images are pinned: LinuxServer.io's `x.y.z-lsNNN`, the official MariaDB and FileBrowser Quantum by digest.

- **Adding an app**: put it in its group's directory, or a new group with its own `namespace.yaml`, `kustomization.yaml` and a Flux Kustomization in both `k8s/clusters/*/apps.yaml`, its name in `kubernetes_app_groups` (`group_vars/all/kubernetes.yml`) and a section `k8s/apps/homepage/tiles/<group>.yaml.tmpl` in Homepage's `homepage-tiles` generator → a tile in its group's section → a `ClusterIP` Service and an Ingress (`ingressClassName: traefik`, host `<app>.${DOMAIN}`) → its data on a claim of `local`, or a static volume in both `k8s/infrastructure/storage/*/` → probes, a startup probe if it migrates before it listens, requests, `allowPrivilegeEscalation: false` and the `RuntimeDefault` seccomp profile → a `${VAR}` it needs added to `flux_bootstrap_settings` (`group_vars/kubernetes/flux.yml`) and `tests/fixtures/cluster-settings.yaml` → a Secret as a SOPS file (`k8s/README-secrets.md`) → a database as a Deployment of its own labelled `app.kubernetes.io/component: database`, which `just suspend` stops after the app and `just resume` starts first → in its namespace's NetworkPolicy, any new path in or out (a new group gets a policy of its own, like the others) → if it needs more than baseline (`privileged`, a hostPath, host networking, added capabilities), a namespace labelled `pod-security.kubernetes.io/enforce: privileged` with a comment saying why, `ignore-check.kube-linter.io/<check>` annotations, and the namespace in `PRIVILEGED_NAMESPACES` (`tests/policy/test_k8s.py`) → an immutably pinned image.
- Apps whose Secret does not exist yet (made by the owner, `k8s/README-secrets.md`) wait for it, and their Flux Kustomization does not become ready; the others are not held up.
- **An app `just suspend` stopped is out of Flux's hands until `just resume`**: Flux skips it entirely, so a change merged meanwhile (an image bump) reaches it only then, and one deleted from Git meanwhile is not pruned. `kubectl get deploy -A` shows them at 0, annotated `kustomize.toolkit.fluxcd.io/reconcile: disabled`.

## Storage model

**Each app's own data is a claim on `local`**, the default StorageClass (local-path-provisioner), on the worker's data volume: a Talos user volume on the VM's data disk, which is on the NAS's persistent storage with a NAS and on the installer's storage without one, and which the nightly VM backup covers. Volumes are `Retain` and every data-holding claim, volume and namespace carries `kustomize.toolkit.fluxcd.io/prune: disabled`, so data outlives its manifest. **What several apps share, or what lives on the NAS, is a static volume** of the same name in both setups (`k8s/infrastructure/storage/<setup>/`), bound by `volumeName`/`claimRef`: `media` (the library), `nextcloud-data`, `photoprism-media` (PhotoPrism's originals and imports, one mount so an import is a rename) and `frigate-media` (recordings). With a NAS they are csi-driver-nfs volumes on the datasets `roles/truenas` exports to the worker alone (`ephemeral/jellyfin`, `persistent/nextcloud`, `persistent/photoprism`, `ephemeral/frigate`; NFS 4.2); without one, `local` volumes pinned to the worker (`DATA_NODE`): the library and the recordings on its media disk (never backed up) or, with `kubernetes_media_on_data_volume`, on its data volume, the rest on the data volume. A `local` volume makes no directory, so a Job in `local-path-storage` (`static-volume-directories`, the repository's one hostPath, `/var/mnt`) makes each, owned by 1000; it has no TTL (Flux would recreate it), so it runs once and a volume made anew needs it deleted by hand (`vm-restore.md`), and `kustomize.toolkit.fluxcd.io/force: enabled` (its pod template is immutable). **Ownership on the NAS**: the role sets no owner, the shares map root to root, and every pod that mounts `media`, `nextcloud-data` or `photoprism-media` runs an init container `chown-mount` (busybox by digest, as root with `CHOWN` alone) that makes the mount point, never anything below it, uid 1000. No pod sets `fsGroup` on an NFS volume (kubelet would chown the whole library at every start), and csi-driver-nfs has its fsGroup policy off. Jellyfin transcodes to an `emptyDir` on the worker's system disk, never the backed-up data disk.

## Networking

MetalLB (layer 2) hands out `LB_RANGE`; Traefik is the default IngressClass on `LB_TRAEFIK_IP`, HTTPS with the cluster's own CA (the Landmines' TLS entry; HTTP redirects, Jellyfin aside), and every app is `https://<app>.${DOMAIN}` (`homeserver.internal` unless `local.yml` sets `kubernetes_domain`). **A new cluster serves nothing to the LAN**: every router on Traefik's `web` and `websecure` entrypoints passes the Middleware `traefik/lan-allowlist` (`k8s/infrastructure/configs/traefik.yaml`, an `ipAllowList` of `INGRESS_ALLOWED_RANGE`), which is the loopback address, so a 403 for every client, until `local.yml` sets `kubernetes_ingress_allowed_range`, once each app's first visit is done through `kubectl port-forward` (`scripts/runbooks/first-run.md`): Nextcloud's, Jellyfin's, Seerr's and SABnzbd's wizards make their first visitor the admin, and Sonarr, Radarr and Prowlarr serve anyone, their API key included, until their first login exists. Those three also set `<APP>__AUTH__REQUIRED=Enabled`: behind Traefik every request comes from a pod's address, which they count as local, so "disabled for local addresses" would open them to the LAN. Traefik's Service keeps clients' addresses (`externalTrafficPolicy: Local`), so the range is matched against the client's own. DNS is a wildcard `*.<domain>` record for `LB_TRAEFIK_IP` in the router, not managed here. No Service opens a node port: NodePort is refused, and so is a LoadBalancer that allocates them. Home Assistant is reached by the name its DHCP reservation gives it in the router's own domain, never under the wildcard, which would send it to Traefik.

## Monitoring

kube-prometheus-stack (chart 92.0.0 from its OCI registry) in `k8s/infrastructure/monitoring/`, with its namespace `monitoring` (privileged, for node-exporter), under its own Flux Kustomization `infra-monitoring` after `infra-controllers`. One replica each of Prometheus (retention `PROMETHEUS_RETENTION`/`PROMETHEUS_RETENTION_SIZE`: 15d/15GB with a NAS, 7d/5GB without; 20Gi on `local`; every ServiceMonitor, PodMonitor and rule in the cluster), Alertmanager (the chart's default, empty receiver: add an e-mail route with a SOPS Secret when wanted; the chart's `KubeCPUOvercommit` and `KubeMemoryOvercommit` are off, since the node they assume the apps could move to is the tainted control plane, so both fire from the first minutes and never clear) and Grafana (`Recreate`, 5Gi on `local`, at `grafana.${DOMAIN}`, the admin password the chart generates: `kubectl get secret -n monitoring kube-prometheus-stack-grafana -o jsonpath='{.data.admin-password}' | base64 -d`). Grafana answers the LAN, so its sidecars read ConfigMaps in `monitoring` alone, through the Role in `grafana-rbac.yaml` (`rbac.namespaced`, `rbac.useExistingRole`; the chart's own role reads every Secret in the cluster, flux-system's age key included), and kube-state-metrics runs without its `secrets` collector, which lists every Secret's values; `test_k8s.py` refuses any other service account outside `kube-system` and `flux-system` that can read every Secret, bar Traefik's (its chart grants it, and narrowing it costs the IngressClass) and the Prometheus operator's (`CLUSTER_SECRET_READERS`). The control plane's controller manager and scheduler are static pods Talos labels `component: <name>`, which the chart's Services select, scraped over HTTPS without verification; etcd is not a pod on Talos, so its Service selects the API server's static pod, which runs in the control plane's host network, where etcd serves its metrics (port 2381, plain HTTP): no address is written anywhere; all three serve beyond localhost because roles/talos binds them to 0.0.0.0. The plain-HTTP scrapes (etcd, kube-proxy, CoreDNS) carry no credentials (`serviceMonitor.authorization: null`): the chart would send Prometheus's service account token with each, in clear, though none asks for one, and `test_k8s.py` refuses a rendered monitor that sends a token over HTTP. Every component has requests, which `just lint charts` checks on the rendered chart (rendered without its test pods, which Flux never runs). The Proxmox host's own exporter (`roles/proxmox_node_exporter`) is one more target, `${PROXMOX_ADDRESS}:9100`, in the chart's `additionalScrapeConfigs` rather than a `ScrapeConfig`, a kind the release's own CRDs bring, which a fresh cluster would refuse in the same Flux Kustomization before the chart is installed. Its job is the nodes' exporters' own, `node-exporter`, so the Node Exporter dashboards list the host beside the nodes, by address, and the chart's node alerts cover it (a filesystem filling, a failed systemd unit, a degraded RAID); the cluster-wide USE dashboard then counts the nodes' share of the host twice, since the host's CPU and memory include every guest's. The exporter answers only the nodes' addresses, which Prometheus's scrapes leave the worker with.

## GPU

Whether the host passes its Intel iGPU to the cluster is per host: `local.yml`'s `kubernetes_gpu_mapping`, the id of a Proxmox PCI resource mapping made by hand (`scripts/runbooks/gpu.md`, which also has the host's VT-d and `vfio-pci` steps). With it, the worker (`kubernetes_data_node`) gets `hostpci0` (`group_vars/proxmox/vms.yml`), the `gpu` schematic with Intel's i915 extension and the label `homeserver.internal/gpu: intel` (`group_vars/kubernetes/talos.yml`); Flux's `infra-gpu` applies Intel's GPU plugin from `k8s/infrastructure/gpu/`: upstream's v0.37.1 manifest, vendored with only its namespace edited, its image pinned by digest and the rest patched in the directory's `kustomization.yaml` (`-shared-dev-num=2` and that node selector), in the privileged namespace `intel-gpu-plugin`, which the directory declares (its `README.md` says how to bump it); and the settings say `GPU_I915` `1` and `FRIGATE_DETECTOR_DEVICE` `GPU`. Without it, `0` and `CPU`. The manifests are the same either way: Jellyfin and Frigate set `gpu.intel.com/i915: "${GPU_I915}"` as a limit, and a limit of `0` asks for nothing, so they schedule on a node without the plugin. Frigate's detector device is written into its configuration only when the seed copies it, at the first start, so adding a GPU later means changing it in Frigate's editor. Restarting the VM for `hostpci0` and the `just talos-upgrade` for the schematic are by hand.

## Images and requests

- **Every image is pinned by tag and digest.** A tag can be moved to other contents, a digest cannot: the tag says what the image is, the digest what is pulled (`image: docker.io/linuxserver/sonarr:4.0.19.2979-ls320@sha256:…`). `tests/policy/test_k8s.py` refuses an image without a digest, in the manifests, in the charts' rendered output (`just lint charts`), in a container's flags (cert-manager's ACME solver, the Prometheus operator's config reloader) and in a Prometheus or Alertmanager. A chart's images are pinned in its release's values, each chart by its own keys (`tag: <version>@<digest>`, or a `digest` or `sha` beside the tag, kube-prometheus-stack's `sha` without the `sha256:` prefix but kube-state-metrics' with it), so **bumping a chart means bumping the images its values pin**, whose tags are then the chart's new defaults: until then the old images run. A vendored file keeps upstream's tag and its `kustomization.yaml` adds the digest (`images:`). Resolve a digest from the registry, which needs no Docker: `crane digest <image>:<tag>`, or `docker buildx imagetools inspect`. LinuxServer.io images come from Docker Hub (the same digests as lscr.io and ghcr.io), and use the `x.y.z-lsNNN` tags, since LinuxServer.io re-points plain `x.y.z` at every build revision. Do not add `imagePullPolicy: Always`: kube-linter rejects it, and any image without a tag or tagged `latest`.
- **Resource requests on every workload** and every chart component (kube-linter requires CPU and memory requests, `just lint charts` on the charts' output too), and no CPU or memory limits on the apps, so a spike is neither throttled nor OOM-killed (`test_k8s.py` refuses one; Jellyfin's and Frigate's one limit, `gpu.intel.com/i915`, asks for the iGPU). All values are un-measured guesses. Summed from the rendered manifests, the apps request about 2.5 vCPU and 7.5 GiB together, and the platform on the worker (the charts, the DaemonSets and CoreDNS) requested 1.3 vCPU and 2.7 GiB on a test host without a NAS (2026-10-20), so the worker that runs them needs at least 4 vCPU, 12 GiB and a 32 GiB system disk (the images filled a 14 GiB one there), which `kubernetes_settings_error`'s sizing message asks for without a NAS.
- **Renovate** (`renovate.json`) updates what Dependabot cannot see under `k8s/`: container images, HelmRelease chart versions and OCIRepository tags (managers `flux`, `kubernetes`, `helm-values`, `kustomize`), each release at least 7 days old where its registry gives a release time (`minimumReleaseAgeBehaviour: timestamp-optional`: only Docker Hub does, and Renovate 42's default would hold every ghcr.io and quay.io image and the OCI charts back for good; `test_k8s.py` checks it), and an image or OCI chart from any other registry (ghcr.io, quay.io, registry.k8s.io) only once approved on the Dependency Dashboard, since the age gate cannot hold it back; with `pinDigests`, so each image keeps its digest and a tag moved upstream becomes a pull request; each chart in one pull request with the images its release pins (`groupName` by directory); commits prefixed `[dependencies]`. LinuxServer.io's tags need one versioning rule per shape (`x.y.z.build-lsN` for sonarr, radarr, prowlarr; `x.y.z-lsN` for sabnzbd and nextcloud; Jellyfin's `x.y.zubuNNNN-lsN`, the Ubuntu release a compatibility; MariaDB's `x.y.z-rN-lsN`): a tag no rule parses would never be updated, security releases included, and `test_k8s.py` checks that each image matches exactly one rule. local-path-provisioner's and Intel's GPU plugin's directories are excluded (each re-vendored by hand). It does not touch the FluxInstance (Ansible's) or the Talos pins, which stay hand bumps. It runs once the owner installs the Mend Renovate app, after the ruleset split (TODO.md). Read each PR before merging: Flux deploys `main` as soon as it lands. FileBrowser Quantum publishes security releases often; a Homepage release can add a skeleton configuration file, which the emptyDir it copies its configuration into absorbs, but check its first start. `just lint github` validates `renovate.json` against check-jsonschema's bundled schema.

## Landmines

- **TLS comes from the cluster's own CA, which each device must trust.** `*.homeserver.internal` cannot be validated by public ACME, so cert-manager signs a 90-day wildcard with a private root CA (`k8s/infrastructure/tls/homeserver-ca.sops.yaml`, ten years, `nameConstraints` limiting it to names under the domain and excluding every IP address, which a constraint on DNS names alone leaves open, so its key could vouch for nothing else) and renews it; Traefik serves it as its default certificate (TLSStore `default`), redirects HTTP to HTTPS and adds HSTS. The owner installs the CA's certificate on each device (`scripts/runbooks/tls.md`, which also remakes it for another domain). Jellyfin alone also answers plain HTTP (its Ingress's router priority, 1001, outranks the redirect's, 1000), since its TV and streaming-box apps cannot trust a private CA: what they send crosses the LAN in clear. A real domain with DNS-01 would remove both the device step and that exception (`TODO.md`). The old `k8s/cert-manager/` (v1.4.0, staging ACME, microk8s solver class) was deleted long before.
- **No app is privileged.** Jellyfin and Frigate used to be, for `/dev/dri`; now Intel's GPU plugin hands them the device (`gpu.intel.com/i915`), and every app namespace stays at `baseline`. The privileged namespaces are the platform's, each with a comment saying why: `metallb-system` (the speaker's host network), `local-path-storage` (its helper pods' host paths), `monitoring` (node-exporter) and `intel-gpu-plugin` (the plugin's host paths); csi-driver-nfs runs in `kube-system`, which Pod Security exempts. `PRIVILEGED_NAMESPACES` and `CHART_PRIVILEGED` in `test_k8s.py` list them. Home Assistant runs as a VM (Home Assistant OS), so its manifests went.
- **No plaintext `Secret` manifest may be committed.** Every Kubernetes Secret is a `k8s/**/*.sops.yaml` encrypted with SOPS for the cluster's age key (`.sops.yaml`: values only, `data` and `stringData`), which Flux decrypts with the `flux-system/sops-age` Secret `roles/flux_bootstrap` keeps; `k8s/README-secrets.md` says how to make one without the plaintext touching the disk, and lists the Secrets the apps need. `.gitignore` blocks `k8s/**/*secret*.yaml` in both letter cases, with negations for the safe-by-construction kinds (`*.sops.yaml`, `*.example.yaml`, `*.template.yaml`, `externalsecret*.yaml`, `secretstore*.yaml`). gitleaks's `k8s-plaintext-secret` rule (YAML and JSON under `k8s/`, where `test_k8s.py` allows nothing but YAML, `.tmpl` and `.md`) allows every `*.sops.yaml`, so `scripts/ci/check-sops-staged.sh` refuses one that was never encrypted (a document without `sops:`, or a value under `data` or `stringData` that is not `ENC[`): on the staged files in the pre-commit hook (`scripts/ci/check-staged.sh`), and on every version in the pushed commits through `check-range.sh` (pre-push and CI). `.sops.yaml` names the owner's age key as the recipient; a fork puts its own there. The homepage service-account token stub is gone, with its allowlist entry. **This repo is public** — that is also why `inventory` and all of `.claude/` but its rules are ignored.
- **NetworkPolicies are enforced, so a new path between pods needs a rule.** Talos's Flannel runs its policy agent, kube-network-policies (a `KubeFlannelCNIConfig` control-plane patch, `talos_patch_network_policies`); without it every NetworkPolicy is accepted and ignored. Each app namespace has one policy over all its pods (`k8s/apps/<group>/network-policy.yaml`, which `test_k8s.py` requires): in, only its own pods, Traefik and Homepage (Frigate: its UI from Traefik and Homepage, its streams from anywhere, never its unauthenticated API on 5000, which only the kubelet's probes reach, from the node); out, anywhere but the NAS (`EGRESS_DENIED_ADDRESS`), whose NFS exports trust the worker's address, which pods' traffic leaves the node with, and the Proxmox host (`PROXMOX_ADDRESS`), whose API and SSH answer the LAN, in both setups (without a NAS both name the host; only its main address, never another it may have). In `monitoring`, Prometheus, Alertmanager and kube-state-metrics answer only that namespace and Grafana also Traefik. An app that must reach another namespace, or the NAS, needs its policy changed, or it times out. **A pod's first seconds are judged without its policy**: the agent learns a new pod's address from the API, after the pod has started, so a fresh pod's first connections go through unchecked (a test pod in a deny-all namespace reached the NAS at once and was blocked 15 seconds later), and packets from the node to it may be dropped then (a new Homepage pod's probes were, for three seconds, and retried). containerd's NRI would let the agent see a pod as it starts, but Talos keeps NRI off by default, since any pod with its socket could rewrite containers, and it would take restarting the nodes: left so (2026-10-17). Flux's own policies (the FluxInstance's) apply in `flux-system`. What a policy drops is in the agent's log on the node that dropped it, each `Packet denied` three lines after the `Evaluating packet` line naming its source and destination: `kubectl -n kube-system logs -l k8s-app=flannel -c kube-network-policies --prefix --tail=-1 | grep -B3 'Packet denied'`. Talos runs the agent at `--v=2`, which logs every packet it judges (12,000 to 15,000 lines an hour on a worker running the apps, as traffic goes, with the start of each packet in hex), and its configuration has no setting for it; kubelet's log rotation bounds it, and the API server's proxy to a pod a policy closes (`kubectl get --raw .../proxy/...` to Prometheus) times out and shows there too.
